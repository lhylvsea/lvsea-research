# 研究驱动的关系图与知识可视化

## 模块定位

`research-diagram` 只处理“先研究、再形成结构、最后可视化”的请求。它是 `lvsea-research` 的输出路由，不是第二个根 Skill，也不是把上游仓库原样搬进来。

上游参考：[wshuyi/research-to-diagram](https://github.com/wshuyi/research-to-diagram)，本次检查的提交为 `c13ec59f3c894da607d7d5b17a18fccdba0bc389`，许可证为 MIT。上游的可复用方法是把研究拆成来源收集、实体/关系提取、结构设计、Graphviz DOT 生成和 PDF/矢量输出；其 Claude Code、WebSearch、macOS Homebrew 和速度/数量示例不被视为本包已具备的能力。

## 路由边界

### 进入本路由

- 没有现成结构化数据，需要研究人物、组织、概念、技术组件、工艺流程或事件之间的关系；
- 用户明确要求关系图、知识图谱、概念图、架构图、流程图、时间线图或 PDF/SVG/PNG 等可视化交付；
- 研究结论的价值依赖于实体、层级、依赖、因果或协作关系的可见化。

### 不进入本路由

- 只想把已有 DOT、JSON、CSV 或人工整理的关系表转换为文件：这是渲染/转换动作，不应假装成研究；可直接使用 `scripts/render_diagram.py`；
- 只要一张装饰性图片、海报或营销页面；
- 只有一个事实或一条 URL，图谱不会增加判断价值；
- 关系无法从来源、用户材料或明确推理链得到支持。

如果请求同时包含明确决策、法规核验或故障诊断，仍以决策、事实核验或诊断为主路由；图只作为交付格式或协作产物。

## 标准流程

1. **锁定图的用途**：明确受众、研究问题、时间范围、地域、输出格式和“图要帮助用户看见什么”。
2. **建立来源计划**：先读用户材料，再按主题、实体、关系、反例和当前状态分线检索。搜索摘要只能发现来源，不能直接支撑节点或边。
3. **建立证据账本**：每个关键节点和关键关系至少记录来源 URL、主张、来源等级、时间、独立性、局限和证据状态。未知关系标为未知，不用布局需要替代证据。
4. **抽取结构**：将材料整理为节点、节点类型、属性、关系类型、方向、时间和置信度；区分来源事实、来源解释、本次推断和用户提供内容。
5. **选择视觉语法**：人物/组织优先分组关系网或层级图；概念优先层级/有向图；技术和工艺优先分层架构或数据流；历史对象可用左到右时间线加事件关系。
6. **先总览后细化**：默认控制总览图复杂度，复杂主题拆为总览图和 1–N 张细节图。上游提出“约 50 个节点以内”的经验值，仅作为可读性启发，不是硬性质量承诺。
7. **生成并检查 DOT**：优先 Graphviz。通过 `scripts/render_diagram.py` 使用无 shell 的跨平台调用，支持 PDF、SVG、PNG；输出已存在时必须显式传 `--force`。
8. **视觉与事实 QA**：检查文字是否可读、中文字体是否可用、箭头方向是否正确、关系标签是否歧义、图例是否完整、关键边是否有来源，以及输出文件是否真的生成。
9. **交付来源**：与 DOT 和最终图一起交付 `*_sources.md` 或证据账本；没有实际 provider 调用或人工盲评时，明确写 `missing_evidence`，不把静态渲染通过说成研究质量已验证。

## 图形设计规则

### 节点和关系

- 颜色表示类别或证据状态，不用颜色强行表达未经证实的好坏；
- 形状表示实体类型，边标签表示关系语义；实线、虚线、箭头和粗细只在图例中有明确含义时使用；
- 使用 `subgraph cluster_*` 表达组织、阵营、层级或系统边界；
- 同一关系的方向和命名保持一致，避免将“依赖”“影响”“并列”画成同一种边；
- 关键节点可以加属性，但不要把长段落塞进节点。证据详情放在来源文件或账本。

### 布局选择

| 主题结构 | 优先布局 | 适用说明 |
| --- | --- | --- |
| 组织、家族、层级 | `TB` | 自上而下看层级与隶属 |
| 流程、时间线、数据流 | `LR` | 从左到右看阶段、顺序与方向 |
| 依赖、逆向追踪 | `BT` | 从结果回溯上游 |
| 关系网络 | `TB` 或 `LR` | 先按群组分层，再处理交叉边 |

如果需要 PlantUML 或 Mermaid，只有在宿主真实具备并已验证对应渲染器时才使用；上游列出这些选项不等于本包已安装它们。

## 跨平台渲染

检查 Graphviz：

```text
dot -V
```

渲染已审核的 DOT：

```text
python scripts/render_diagram.py diagram.dot --format pdf --output output/diagram.pdf
python scripts/render_diagram.py diagram.dot --format svg --output output/diagram.svg
```

中文字体应按宿主实际安装情况选择，例如 `Microsoft YaHei`、`SimHei` 或 `Arial Unicode MS`，不要在没有检查的情况下保证中文不会乱码。脚本不会执行用户输入的 shell 字符串，也不会自动下载 Graphviz。

## 研究输出契约

最小交付包括：

- `*_relations.dot`：可继续修改的结构源文件；
- `*_relations.pdf`、`*.svg` 或 `*.png`：仅在实际渲染成功后声明已生成；
- `*_sources.md` 或 `evidence_ledger`：节点/关系到来源的映射；
- 一段结论：图表达的主结构、尚不确定的关系、反例和下一步验证。

图谱不是证据本身。关系越关键，来源映射和反证要求越高；无法核验的边要删掉、降级标注或放入“待验证”区域。
