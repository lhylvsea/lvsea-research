# 路由手册

## 选择顺序

先判断用户要解决的是“取信息、判断真假、形成解释、做选择、找机制还是做交付”。不要因为出现“研究”二字就自动走深研。按以下顺序收敛：

1. 用户明确指定的格式、方法或工具。
2. 是否涉及医疗、法律、财务或其他高风险领域。
3. 是否存在明确的行动决策。
4. 是否需要比较、历史类比、时间线或问题诊断。
5. 对象是否陌生、动态、争议性强或需要多来源。
6. 研究深度和输出格式。

## 路由组合

| 主路由 | 可选协作 | 何时组合 |
| --- | --- | --- |
| fast-retrieval | fact-check | 一个事实但来源有争议或会变化 |
| deep-research | fact-check、benchmark-comparison | 研究对象有当前竞争或关键数字 |
| timeline-cross-section | benchmark-comparison、fact-check | 需要解释历史如何塑造当前位置 |
| decision-analysis | fact-check、benchmark-comparison | 选择依赖外部事实或替代方案 |
| problem-diagnosis | decision-analysis | 先把问题问对，再选择行动 |
| historical-analogy | fact-check、decision-analysis | 历史机制完成后才需要现实试验 |

最多保留一个主路由和两个协作路由。没有证据支持协作价值时，不调用协作路由。

## Provider 选择

- anysearch：优先用于需要实时检索、垂直领域子域发现、批量搜索和全文抽取的场景。垂直查询先发现子域和必需参数，再调用查询。
- multi-search-engine：若本机有可核验的无密钥多引擎工具，用于地区/语言/时间/站点/文件类型的覆盖和结果对照。它是覆盖工具，不是质量排序器。
- 宿主 Web/浏览器：没有专用 Skill 时作为实际检索能力；记录是否真的调用。
- 本地文件/项目数据：涉及用户给定资料时优先读本地事实，不用外部搜索覆盖内部数据。
- Provider 不可用：保留研究问题和来源计划，切换到可用路线，标记降级原因；不把配置存在写成已调用。

## 研究深度与停止

- quick 只解决当前问题，不主动扩展成时间线、竞品或完整报告。
- standard 至少完成一次独立复核和一次反面检索。
- deep 建立多条信息线，关键事实至少两类来源支撑，结论必须列出反证和缺口。
- 当关键事实无法核验、来源高度相关、用户未授权外部检索或外部风险不可接受时，停在“当前可证实范围”，明确下一步需要什么证据。
